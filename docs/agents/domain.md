# 内部黑话词典与技术拍板备忘录规则（`domain.md`）

> **通俗解释**：`domain docs` 就是项目的**「内部黑话词典 + 历史拍板备忘录」**。规定 AI 在写代码前必须先读这两样东西，不准自己瞎编乱造名词，也不准推翻你之前已经拍板定死的技术决定。

## 一、AI 动手前必须先读的文件

1. **根目录下的 [`GLOSSARY.md`](../../GLOSSARY.md)（内部黑话与统一用词词典）**：规定项目里的每个核心概念统一叫什么名字、禁止叫什么别称。
2. **[`docs/adr/`](../adr/) 文件夹（技术选型拍板备忘录）**：`ADR` 就是「**当初为什么要这么选的技术备忘录**」（比如：为什么把文章直接放在文件夹里而不用复杂后台）。

## 二、文件结构

```text
site-2/
├── GLOSSARY.md              ← 内部黑话与统一用词词典
├── docs/adr/                ← 技术选型拍板备忘录（ADR）
│   ├── 0001-verified-master-stack.md
│   └── 0002-dual-track-3d-and-asset-boundary.md
└── app/                     ← 网站代码
```

## 三、AI 必须遵守的两条铁律

1. **统一口径，不准乱起名**：写工单、写代码、写测试时，必须严格使用 `GLOSSARY.md` 里规定的标准词。
2. **不准偷偷推翻历史决定**：如果 AI 觉得某条已经写进 `docs/adr/` 的技术拍板需要调整，必须先开口向你报告，绝不准偷偷违背。
