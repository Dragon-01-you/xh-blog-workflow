# 拍板备忘录 0002：用自己掌控的 150 行轻量文章读取管线，不用第三方重型内容框架

> **对标原版**：`cali.so/docs/adr/0002-mdx-pipeline-owned-not-framework.md`
> **状态**：已拍板生效（Accepted）

---

## 一、我们要解决什么问题？（背景）
既然拍板决定了把文章放在 `content/blog/` 文件夹里（见备忘录 0001），那怎么把文件夹里的笔记变成漂亮的网页呢？
很多新手教程会让你装一堆叫 `Contentlayer` 或 `Velite` 的第三方重型内容打包插件。但 `cali.so` 作者发现：这些第三方插件经常停止维护（比如著名的 `Contentlayer` 就直接烂尾停更了），一旦网站升级 Next.js 框架，整个博客直接报错编不出网页。

## 二、我们的拍板决定
**拒绝第三方重型内容框架，自己写一个只有 150 行左右、100% 自己掌控的轻量读取管线（`lib/content.ts`）**：
1. 用 Node.js 自带的 **`fs`（文件读取器）** 扫描 `content/blog/` 文件夹；
2. 用 **`gray-matter`（头部信息提取器）** 把文章最顶部的标题、日期、摘要拆出来；
3. 用 **`zod`（信息安检员）** 自动检查每篇文章有没有漏写标题、日期格式对不对（漏写立刻提醒你）；
4. 用 **`marked` + `shiki`（印刷级代码染色器）** 把正文和代码块染成漂亮的网页，并自动算出这篇文章有多少字、需要读几分钟、有哪些章节目录（供左侧迷你标尺使用）。

## 三、为什么这么选？（好处与代价）
- **核心好处**：代码不到 150 行，没有任何黑盒魔法，以后不管 Next.js 怎么升级，永远不会因为第三方插件停更而卡死。
- **死规矩**：未经重新讨论，严禁 AI 把这套轻量管线擅自“升级”成复杂的第三方内容框架。
