# 03 · README 黄金结构

> 读者只给你 8 秒。这 8 秒里他要看到：这是啥、有没有图、能不能马上跑、别人怎么说。

## 1. 结构（从上到下，不要改顺序）

```
Hero 图（width=100%）
# 项目名
*English pitch*
一句话定位（加粗）
语言切换 + 徽章矩阵
---
## 这是什么（说人话：类比 → 定义）
### 它能回答 N 个问题（表格）
## 30 秒演示（GIF / mp4）
## 目录
## 快速开始（环境要求表 → 三步）
## 工作原理（图 + 表）
## 技术实现（技术 × 用途表）
## 对比同类项目（表格）
## 实际案例（脱敏）
## 常见问题（<details>）
## 路线图（复选框）
## 参与贡献
## 使用须知与免责声明
## Star 历史
```

## 2. 首屏的四个硬指标

1. **图**：Hero 图 + 至少一张原理图 + 一个动态演示
2. **一句话**：H1 之后立刻说明"给谁、解决什么、产出什么"
3. **可动作**：首屏内能看到 `pip install` / `npm i` 或"三步上手"的锚点
4. **可信**：CI 徽章是绿的、License 明确、有版本号

## 3. 排版微规则

| 项 | 规则 |
|---|---|
| 表格 | 窄列用 `|:---:|` 居中；数字列右对齐 |
| 图片 | 统一 `<img width="88%"/>` 居中，宽度不要混用 |
| 章节 | H2 之间用 `---` 分割，制造呼吸感 |
| FAQ | `<details><summary>问题</summary>` 折叠，问题用用户原句 |
| 代码块 | 每个都标语言；命令用 `bash`，输出用 `text` |
| emoji | 只用在章节标题，每节最多一个；正文不用 |

## 4. 锚点（最常翻车的地方）

GitHub 的锚点规则：

```
## 🚀 快速开始   →   #-快速开始        （emoji 变一个前导连字符）
## 🔐 可验证推理证明（v0.7） → #-可验证推理证明v07  （标点与空格被删）
```

**安全做法**：目录里的链接写完后，点一遍。或者干脆让标题不带 emoji、不带括号。

## 5. 双语 README

- `README_EN.md` 必须是**同构**的：章节数、表格列、图的顺序都一致
- 顶部互相切换：`[中文](README.md) · [English](README_EN.md)`
- 不要机器翻译腔：英文版重写，不是逐句直译
- 中文版可以更长、更口语；英文版更短、更直接

## 6. 内容诚实度（决定长期口碑）

- 案例必须脱敏：站点用代号（"Relay-X"），保留方法与数字
- 有缺陷就写：`## 已知限制` 比藏着更可信
- 数字给条件："在 8 次采样下，p<0.001"
- 不写"业界第一"——写"我们与 X 的差异是 Y"

## 7. 常见错误清单

- [ ] 首屏是目录而不是价值
- [ ] 徽章 12 枚，全在闪
- [ ] 图片用绝对路径（换域名就裂）
- [ ] 演示 GIF 是伪造/摆拍的
- [ ] FAQ 是自问自答的软文问题
- [ ] Roadmap 全是 `[ ]`，没有一个已完成
- [ ] 中英版内容不一致
- [ ] README 里的命令跑不通（最伤）
